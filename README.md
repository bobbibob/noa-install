## Что такое N.O.A

N.O.A собирает AI-агентов, задачи и инструменты в одну многоагентную студию. Каждый агент получает свою роль и отдельную сессию. Для совместной работы есть комнаты, отделы и общая шина сообщений.

**Человек → главный агент сети → руководители отделов → исполнители → результат.**

Работать с платформой можно в браузере, как с PWA или через Android-приложение. В репозитории лежит «голая» платформа: веб-приложение, мастер первичной настройки, механизм обновлений и базовый набор модулей. Ваших агентов, переписки, медиа и ключей в ней нет.

Обзор проекта, схемы и скрины — в витрине [N.O.A](https://github.com/bobbibob/N.O.A).

## Возможности

| Направление | Что есть |
| :--- | :--- |
| **Агенты** | Отдельные сессии и роли, монитор работы, закреплённые сессии, перенос агента в пакете `.age` |
| **Команда** | Комнаты, отделы, внутренняя переписка, общий журнал задач агентов |
| **Задачи** | Разовые задания, матрица Эйзенхауэра, баннер текущей задачи |
| **Навыки** | Мастер «Обучить агента», галерея готовых ролей |
| **Модули** | Каталог с установкой в один клик и просмотром прав |
| **Наблюдение** | Здоровье платформы, расход ИИ, статус подключений |
| **Обновления** | Сначала канарейка и смоук-проверка, при сбое — автооткат |

## Требования

| | Минимум |
| :--- | :--- |
| ОС | Ubuntu 22.04 / 24.04 или Debian 12, x86_64 или arm64, доступ root |
| Ресурсы | 2 ГБ памяти, 10 ГБ диска |
| Сеть | Интернет для загрузки зависимостей; панель на порту 3080, наружу — через nginx или Caddy с HTTPS |
| Модель | Ключ провайдера модели, например Claude или OpenAI, — вводится в мастере |

Node.js и OpenCode установщик ставит сам: если в системе нет Node.js 20+, он ставит Node.js 22.

## Установка

**Одна команда на Linux (Debian/Ubuntu), без аккаунта GitHub и без токена:**

```bash
curl -fsSL https://raw.githubusercontent.com/bobbibob/noa-install/main/get.sh | bash -s -- <имя-сети> --host <домен>
```

Имя сети и домен обязательны — без них установщик остановится с подсказкой. Всё, что после `--`, передаётся в `install.sh` (см. «Linux: подробности» ниже). `get.sh` скачивает архив релиза и сверяет его SHA-256 (сумма записана в самом `get.sh`) до распаковки; при несовпадении установка не запускается.

Без `get.sh`, вручную:

```bash
curl -fsSLO https://github.com/bobbibob/noa-install/releases/latest/download/noa.tar.gz && echo "<SHA256>  noa.tar.gz" | sha256sum -c && tar xzf noa.tar.gz && sh noa/install.sh <имя-сети> --host <домен>
```

Замените `<SHA256>` суммой для текущего релиза — она указана на странице релиза ([Releases](https://github.com/bobbibob/noa-install/releases/latest), файл `noa.tar.gz.sha256`), а не внутри этого README: хэш зависит от содержимого архива, в который входит и сам README, поэтому зашить его сюда заранее невозможно. Скачанный архив сверяется с суммой *до* распаковки и запуска; при несовпадении `sha256sum -c` останавливает команду. `sudo` в команде не нужен: `install.sh` сам запросит права, если потребуется.

Это отдельный публичный пакет (`bobbibob/noa-install`): собранный и минифицированный код, без исходников на JS, без `.map` и без истории git. Основной репозиторий платформы (`bobbibob/N.O.A-platform`) остаётся приватным. Пакет не связывается с серверами авторов и не проверяет лицензию онлайн — условия использования см. в `LICENSE`.

Установщик спросит: «Установить локально или на VPS-сервер?». Для VPS он запросит хост, порт, пользователя и ключ или пароль SSH и поставит платформу на этот сервер. Копия не обращается к серверам авторов, не передаёт телеметрию и не содержит чужих ключей: свои аккаунты и модели вы подключаете сами, OpenCode ставится вместе с платформой.

На любой ОС первый вопрос один: **«VPS (SSH)»** (платформа ставится на сервер, команда запускается с вашего компьютера) или **«этот компьютер»**. Выбор можно задать флагом `--target vps|local` (`-Target` в PowerShell).

| ОС | Команда |
| :--- | :--- |
| **Linux** (Debian/Ubuntu, root) | `sh install.sh <имя-сети> --host <домен>` |
| **macOS** | `bash install.command` (или двойной щелчок по `install.command`) |
| **Windows** | `powershell -ExecutionPolicy Bypass -File install.ps1` |

- **VPS (SSH):** укажите `user@host`; пакет копируется на сервер и ставится там как на Linux. Пример: `bash install.command --target vps --ssh root@203.0.113.5 --host noa.example.org`.
- **Этот компьютер:** на Linux — установка напрямую; на macOS и Windows платформа запускается в контейнере (нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/)), сайт откроется на `http://127.0.0.1:3080/`. Нативный запуск без Docker на macOS/Windows пока не поддерживается: код платформы использует пути Linux (`/opt/noa`).

### Linux: подробности
Скачайте архив пакета со страницы релиза и выполните:

```bash
tar xzf noa-platform-ref-<TAG>-pkg.tar.gz && cd noa-platform-ref
sudo sh install.sh <имя-сети> --host <ваш-домен> --admin <ID-сессии-администратора> --tz Europe/Moscow
```

| Параметр | Назначение |
| :--- | :--- |
| `<имя-сети>` | Короткое имя вашей установки |
| `--host` | Домен панели. Можно указать несколько. Без него панель доступна только через ssh-туннель |
| `--admin` | ID сессии администратора сети |
| `--port` | Порт веб-приложения, по умолчанию `3080` |
| `--tz` | Часовой пояс, например `Europe/Moscow` |
| `--no-deps` | Не ставить Node.js и OpenCode |
| `--no-systemd` | Запуск без systemd, например в контейнере |
| `--fp`, `--url` | Автообновление: отпечаток ключа подписи и адрес обновлений. Отпечаток берите у издателя пакета по отдельному каналу; без `--fp` автообновление выключено |

`<TAG>` — версия пакета. Целостность архива можно проверить командой `sha256sum -c *.sha256`. Установщик проверяет окружение, ставит платформу, запускает службу `noa-web` и проверяет, что панель отвечает.

Проверка установщиков идёт в GitHub Actions (`install-check`): Linux — полная установка в контейнере и ответ сайта; macOS и Windows — разбор скриптов и проверка выбора режима (в раннерах GitHub нет Linux-контейнеров на этих ОС).

## Первый запуск

1. Откройте `https://<ваш-домен>/` — запустится мастер первичной настройки из 7 шагов. Без домена: `ssh -L 3080:127.0.0.1:3080 <сервер>` и `http://127.0.0.1:3080/`.
2. Пройдите шаги мастера: сеть, администратор, провайдеры моделей, модули. После шага «Готово» платформа применяет настройки сама.
3. Поставьте главному агенту сети первую задачу.
4. Добавьте нужные модули на странице «Модули» — перед установкой видно, какие права они получат.

## Обновление

Распакуйте новый пакет и выполните:

```bash
sudo sh install.sh --update
```

Перед обновлением установщик сохраняет копию кода; настройки не меняются.

## Удаление

```bash
sudo sh install.sh --uninstall
```

Данные при этом остаются. Чтобы удалить и их (настройки, модули, каталог): `sudo sh install.sh --uninstall --purge --yes`. Node.js и OpenCode остаются в системе.

## Вопросы и ответы

<details>
<summary><b>Почему не работают push-ссылки?</b></summary>

Нужно указать адрес панели — флагом `--host` при установке или в мастере.
</details>

<details>
<summary><b>Что нужно для работы агентов?</b></summary>

Ключ провайдера модели, например Claude или OpenAI. Его вводят в мастере первичной настройки.
</details>

<details>
<summary><b>Можно ли поставить N.O.A на домашний компьютер?</b></summary>

Да, если на нём Ubuntu 22.04 / 24.04 или Debian 12. Без домена панель открывается через ssh-туннель.
</details>

<details>
<summary><b>Можно ли использовать N.O.A в коммерческих целях?</b></summary>

Да, бесплатно. Распространять можно только целиком и без изменений. Условия — в [LICENSE](LICENSE).
</details>
